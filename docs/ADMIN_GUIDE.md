# 管理员手册

## 账号与首次登录

开发环境提供以下演示账号，初始密码均为 `ChangeMe123!`：

| 身份 | 账号 | 核心范围 |
|---|---|---|
| 学生 | `student01` | 查询、本人预约与签到签退 |
| 教师 | `teacher01` | 查询、教师身份预约与签到签退 |
| 实验室管理员 | `labadmin01` | 仅负责实验室的资源、审批、现场和统计 |
| 系统管理员 | `sysadmin01` | 全局用户、角色、资源、参数、审计和统计；纯管理员不能预约 |

演示数据只在 `dev`/测试 profile 加载。首次登录必须把初始密码改为至少 12 位、同时含大小写字母、数字和特殊字符的新密码；改密后系统撤销旧会话并要求重新登录。

连续五次密码错误会临时锁定。系统管理员可在“用户与角色”查看状态并更新账号；禁用用户、改角色或改密码都会使其旧会话失效。

## 用户、角色与导入

系统管理员在“用户与角色”可分页筛选、新建、修改、启禁用用户并分配角色。角色变更使用版本号防止覆盖他人修改；内置系统管理员角色有保护约束，不能被破坏性修改。

CSV 导入由“批量导入”提交，处理结果按任务保留总数、成功数和逐行失败原因。导入前应：

1. 使用 UTF-8 CSV，先在验收环境试导。
2. 确认账号唯一、用户类型为 STUDENT/TEACHER/STAFF、角色编码存在。
3. 下载或记录行级结果，只修正失败行后再导入，避免重复操作。

## 课次、实验室与设备

系统管理员可维护四节大课名称、起止时间和启用状态。修改会校验起止顺序并记录审计。

“实验室管理”包含：代码、名称、楼宇房间、容量、类型、描述、标签、状态、主负责人、学生/教师审批模式、学生可预约、每日上限、提前天数、取消提前分钟数和是否签到。主负责人必须是启用的实验室管理员，保存后同步负责人数据范围。

实验室管理员只能维护分配给自己的实验室；系统管理员可维护全部。状态含启用、停用、维护，非启用状态不能新建或批准预约。

开放规则按星期和课次整体保存；特殊停用课次必须填写日期、课次和原因。保存前核对现有预约，必要时先通知并由管理员强制取消。实验室详情同时提供周日历和列表，移动端默认列表。

设备需维护资产编码、类别、名称、型号、总数量、所需资质和状态。总量调整前检查未来已批准预约，维护/退役设备不会出现在可申请列表中。

## 审批与取消

学生和教师分别使用实验室配置的 AUTO/MANUAL 策略。即使提交时可用，批准时仍会重新检查实验室状态、开放规则、停用、容量、槽位和设备库存。

在“审批与现场”中：

- “通过”会显示申请人、实验室并二次确认；重复点击/网络重试由幂等键保护。
- “驳回”必须填写原因，原因进入通知、状态历史和审计。
- “强制取消”可越过申请人取消截止，但必须填写原因并留下管理员身份。
- 出现版本冲突时刷新列表后重新判断，不覆盖更新。

申请人仅能取消本人待审批/已批准预约，且必须早于实验室 `cancelBeforeMinutes` 截止。非法状态转换返回 `RESERVATION_STATUS_INVALID`。

## 签到签退与爽约

已批准预约在签到窗口内由申请人签到；管理员可在“审批与现场”代签到/签退，并可填写实际人数和备注。所有代操作写入审计。

定时任务会：

- 对超过课次结束仍在使用的预约自动完成。
- 对超过签到宽限期仍未签到的预约标记 NO_SHOW，创建违规和通知。
- 达到爽约阈值时冻结学生预约资格至配置日期。

若人工签到和爽约任务并发，版本更新保证只保留一种合法最终状态。现场争议应以预约历史、考勤记录和审计日志三者核对。

## 通知、统计和审计

站内通知按用户隔离，支持单条/全部已读。外部通知为可插拔本地通道；Outbox 失败会按退避策略重试，达到上限后保留 FAILED 状态和每次尝试记录，不会伪造发送成功。

“统计分析”按日期、实验室、申请人类型和状态筛选，提供：

- 总预约、有效、取消、爽约和学生/教师分类。
- 实验室可用槽位、占用槽位与利用率。
- 高峰课次和设备用量排行。
- 与当前筛选条件完全一致的 CSV；超过 10,000 行时缩小日期/实验室范围。

CSV 会防止以 `= + - @` 开头的单元格触发表格公式。审计日志仅系统管理员可查看，可按操作者、动作、结果和时间筛选；请求 ID 可关联应用日志，但日志不记录密码、Token 或私钥。

## 日常巡检

每日检查待审批积压、失败 Outbox、预约冲突率、5xx、数据库容量和最近备份。每周抽查权限与负责人范围，每月检查依赖扫描与证书有效期，每季度执行恢复演练。操作流程及命令见 [部署手册](DEPLOYMENT.md)。
